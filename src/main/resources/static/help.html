Getting Started

The Airport Simulation lets you model how an airport handles aircraft traffic under different conditions. The basic workflow is:

1

Configure your simulation

Set your input parameters, configure your runways, and optionally schedule specific events. You can also load a previously saved configuration using Load Config.

2

Choose a simulation mode

Select how you want to view the simulation — Quick Sim for instant results or Table View for a live data feed.

3

Start the simulation

Click Start Simulation. Your configuration will be validated first — any issues will be highlighted before the simulation runs.

Review the results

Once complete, view throughput, delay times, cancellations and more. Save your results to compare with future runs using the Comparison Menu.

💡 Use Save Config to store a configuration you want to reuse. Saved configurations can be loaded at any time from the Load Config menu.
Configuration Page

The configuration page is divided into three sections: Input Parameters, Runways, and Scheduled Events.

Input Parameters

Parameter Description
Number of Runways
Range: 1 – 10
 How many runways are active. Use the – and + buttons to adjust. Start with fewer runways and add more to see how throughput scales.
Inbound Rate /hr
Range: 0 – 100
 Average number of aircraft arriving per hour. Aircraft arrive around their scheduled time with some random variation.
Outbound Rate /hr
Range: 0 – 100
 Average number of aircraft departing per hour.
Simulation Duration (mins)
Range: 60 – 1440
 How long the simulation runs in simulated minutes. 1440 minutes = one full day.
Max Departure Wait Time (mins)
Range: 0 – 360
 The maximum time a departure can wait in the take-off queue before being cancelled. Only applies to departures — arrivals are only diverted due to fuel or health emergencies.
Simulation Seed
Range: 0 – 10^7
 Controls the random number generator. Using the same seed with the same configuration produces identical results. Click Generate for a random seed.
Enable Random Events
 When ticked, the simulation randomly generates unplanned runway issues. Note: Clicking the Reset button at the bottom of the page will revert all parameters to their default values and disable random events.
Random Event Multipliers
Range: 0.0 - 10000.0
 Controls how strongly random events are scaled relative to backend baseline probabilities each simulated minute (tick).

Aircraft multipliers (Mechanical, Health) are applied individually for each aircraft currently in the holding pattern. Runway multipliers (Inspection, Snow, Equipment) are applied individually for each active runway.

Example: A multiplier of 2.0 means each individual aircraft/runway is twice as likely as the baseline to experience that event every simulated minute.

Runways

Each runway can be individually configured with a starting status and operational mode before the simulation begins.

Setting Options
Status
 Available: Open and operational.

Runway Inspection: Temporarily closed for inspection.

Snow Clearance: Closed for snow removal.

Equipment Failure: Closed due to equipment failure.

No Change: Leaves the status as-is. Tip: Schedule a "No Change" event to lock a runway and prevent random events from occurring on it during that time.
Mode
 Mixed Handles both arrivals and departures.

Landing Arrivals only.

Take-Off Departures only.

No Change: Leaves the operational mode as-is.

Scheduled Events

Scheduled events let you plan specific incidents at precise times during the simulation. Add an event by filling in the New Event form and clicking + Schedule Event.

Field Description
Type
 Runway — affects a specific runway's status or mode. Aircraft — triggers an emergency for an aircraft in the holding pattern.
Status
 For Runway: Available, Runway Inspection, Snow Clearance, Equipment Failure, or No Change. For Aircraft: Fuel, Mechanical Failure, Passenger Health, or None (operating normally).
Mode
 Only for Runway events. Sets the runway's operational mode at the event time. Automatically locked to No Change if a closure status is selected.
Location
 Which runway the event applies to (Runway events), or Holding Pattern (Aircraft events).
Start Time (mins)
 When the event begins, in simulated minutes. Must be before the simulation duration ends.
Duration (mins)
 How long the event lasts. Leave blank for indefinite. Aircraft events have are automatically indefinite.
💡 Events on the same runway cannot overlap in time — the system will block conflicting events when you try to add them.
⚠️ If you reduce the number of runways after scheduling events, any events on removed runways are flagged in red. Events scheduled at or after the simulation end time are flagged in orange. Both must be resolved before starting or saving.
Simulation Modes

Choose your mode from the dropdown on the configuration page before clicking Start Simulation. Each mode shows the same underlying simulation — the difference is how you observe it.

Quick Sim

Runs the simulation as fast as possible and jumps straight to the results page when complete. No live view.

Best for: Quickly comparing different configurations.
Table View

Shows a live real-time table of runway statuses, holding pattern aircraft, and take-off queue as the simulation runs. You can pause, adjust speed, or stop at any time.

Best for: Monitoring detailed operational data in real time.
Reading the Results

After a simulation completes, the results page shows a breakdown of how the airport performed. The headline metric is Throughput — the total number of aircraft operations (landings + departures) per hour. Higher throughput with lower delays generally indicates a well-configured airport.

Saving & Comparing Results

If you want to keep a record of a simulation, click Save Configuration & Data. Once saved, you can use the comparison tools to analyze different scenarios:

  • Side-by-Side Comparison: Accessed via the Comparison Menu. This view places two saved runs next to each other so you can directly compare configurations, delay metrics, and event logs. Use the Switch button at the top of either column to swap which saved result you are looking at.
  • Compare All: Provides a broad overview of all your saved simulation results at once, making it easy to spot trends across multiple different configurations.
Arrivals
Average Hold Time
Average time aircraft spent waiting in the holding pattern before a runway became available.
Most Planes in Holding Pattern
Peak number of aircraft simultaneously waiting to land. High values suggest runway capacity is a bottleneck.
Maximum Delay Time
The longest any arrival was delayed past its scheduled landing time.
Average Delay Time
Mean delay across all arrivals. Aircraft that land early count as 0 delay.
Number of Diversions
Arrivals diverted to another airport due to a fuel or health emergency while waiting.
Departures
Average Wait Time
Average time aircraft spent waiting in the take-off queue before being cleared for departure.
Most Planes in Departure Queue
Peak number of aircraft simultaneously queued for take-off.
Maximum Delay Time
The longest any departure waited before departing or being cancelled.
Average Delay Time
Mean delay across all departures.
Number of Cancellations
Departures cancelled because their wait exceeded the Max Wait Time setting.
Event Log
A chronological record of all randomly generated emergencies, cancellations, and scheduled events that occurred during the simulation run.
💡 Wait time vs Delay time: Wait time is how long an aircraft sat in a queue or holding pattern — always 0 or greater. Delay time measures how late the aircraft was compared to its schedule. A plane can have high wait time but zero delay if it arrived early enough to absorb the wait.
